    paga-ts

    Unofficial async TypeScript SDK for the Paga Engine API.

    This is an unofficial SDK

    It is not built, endorsed, supported or published by Paga. It is community-maintained and follows Paga's published API reference. Paga's own documentation is the source of truth — if these pages and Paga's disagree, Paga's is right.

    Install

    npm install paga-ts

    Import it as paga.

    Importing as paga

    The package is published as paga-ts. To import it under the short name, alias it in your package.json:

    {
  "dependencies": {
    "paga": "npm:paga-ts@^0.1.0"
  }
}
    import { PagaClient } from "paga";

    Quick start

    const client = new PagaClient(
  process.env.PAGA_PUBLIC_KEY!,
  process.env.PAGA_SECRET_KEY!,
  process.env.PAGA_HASH_KEY!,
  { environment: "test" },
);

const payment = await client.createPayment({
  referenceNumber: "ORD-2026-0187",
  amount: 50,
  payerName: "Bello Ramon",
  payerPhoneNumber: "08064343187",
  payeeName: "Your business name",
  callBackUrl: "https://yourstore.com/webhooks/paga",
});

const status = await client.getPaymentStatus({
  referenceNumber: "ORD-2026-0187",
});

    Conventions

    Two APIs, two auth styles

    How Paga's APIs authenticate
    APIAuthSuccess field
    CollectHTTP Basic plus a hash headerstatusCode (the string "0")
    Businessprincipal and credentials headers plus a hash headerresponseCode (the integer 0)

    Hashing

    Every request that carries a body is signed: SHA-512(concat(hash fields in order) + hashKey), lowercase hex, sent as the hash header. The hash key is never transmitted. A missing field signs as an empty string, and a string value signs verbatim.

    Outcomes

    A 200 response does not mean the money moved. The SDK exposes Paga's code vocabularies and an outcome classifier, so you can tell a definite failure from an undetermined one. Paga's -1, 105 and 135 mean unknown: check the transaction status with the original reference number, never resend.

    Retries

    Only HTTP 429 is retried, and only when you opt in. A server error or a timeout leaves the outcome unknown, so it is never retried automatically.

    Your IP must be whitelisted

    Paga rejects requests from an IP that is not on your allow-list, with a 403. Allow-list your server's addresses before you integrate.
